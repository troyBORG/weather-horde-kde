# Local model discovery

In **Scene**, click **Discover local Comfy models** to reread configured checkpoint directories. It does not select a model, change preferences, start Comfy, download anything, submit a render or apply wallpaper. Excluded models appear in a collapsed, plain-language disclosure. A missing saved selection stays selected and blocks rendering; it is never replaced by the first result.

Discovery uses the trusted installation at `WEATHER_HORDE_COMFY_ROOT`, its `folder_paths` checkpoint directories and optional `extra_model_paths.yaml`. Ordinary subdirectories retain exact relative Comfy identifiers. Duplicate identifiers resolve in Comfy directory priority order; an incompatible first copy is not bypassed for a compatible shadow copy. Directory symlinks are not traversed: configure their target as a checkpoint root explicitly. File targets must remain in configured roots. Broad system roots, excessive inventory and unsafe paths are refused.

Admission is based on bounded safetensors tensor-header evidence for the existing SD 1.5 / SDXL four-channel UNet, conditioning and embedded VAE workflows—not a list of approved filenames. Header objects, tensor shapes/types, offsets, file bounds and duplicate keys are validated; headers are capped at 8 MiB. Pickle checkpoints are never loaded. Inventory is capped at 20,000 entries and 1 MiB of serialized output, with a 15-second configuration/scanning timeout. Model opening uses no-follow descriptor traversal and regular-file checks. The configured Comfy Python and path/configuration modules are trusted executable code, not sandboxed untrusted plugins; GPU/model module imports are denied during discovery.

Known specialized prompt/sampling families (including Pony, Illustrious/Noob, Lightning, Turbo and LCM) are withheld when metadata or identifier hints indicate them. Exclusions distinguish unsupported architecture from an unreviewed family and identify filename hints as hints. These are conservative compatibility checks, **not authenticated provenance**: metadata and filenames can be missing, misleading or renamed. A generic renamed compatible checkpoint is accepted; this does not certify its training family, complete weight integrity or image quality. Style varies even among structurally compatible models.

Explicit selection must also pass a read-only live `CheckpointLoaderSimple` option/output contract check. If Comfy is offline, selection remains unchanged; discovery itself still works offline. Rendering retains its existing local-header refresh, live loader verification and independent activity/VRAM/ownership/queue/consent guards. No discovery path starts Comfy to make a check pass. The existing 4× restoration and independent-wallpaper default are unchanged.

Validation includes malformed-header/path fixtures, fresh multi-directory discovery and duplicate priority, renamed compatible models, explained family exclusions, missing saved selections, zero-submission worker deferral, and authenticated GET refresh in the actual offscreen Plasma loader using the built plasmoid ZIP. Native full-suite results and real local inventory are private delivery receipts, not claims of GPU image quality or owner deployment.
